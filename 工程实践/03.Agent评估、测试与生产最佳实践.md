# Agent评估、测试与生产最佳实践

### 1、Agent评估 vs LLM评估

评估 LLM（模型级别）：

- 只需评估输出文本质量
- 指标：困惑度（Perplexity）、BLEU（词组字面组合 n-gram 重叠率，0-1，越高越好）、ROUGE（n-gram 召回率（该说的说到没），0-1，越高越好）、人工评分

评估 Agent（系统级别）：

- 需要评估整个系统的端到端表现
- 涉及多个维度：任务完成率、工具选择准确率、执行效率等

关键区别：

Agent 的评估更接近【软件系统测试】而非【模型评估】。

Agent 多了一个【行动】维度，需要评估：

- 行动计划是否正确？
- 工具调用参数是否准确？
- 错误处理是否健壮？

评估维度全景：

| 维度 | 评估内容 |
| --- | --- |
| 任务完成率 | 是否成功完成用户指定的任务？ |
| 工具调用准确率 | 是否调用了准确的工具？参数是否正确？ |
| 执行效率 | 完成任务需要多少步？消耗多少token？ |
| 鲁棒性 | 输入异常/工具失败时的处理能力 |
| 安全性 | 是否执行了危险操作 |
| 用户体验 | 回答是否流畅、有帮助、易于理解 |

主流 Agent Benchmark：

- AgentBench: 8 个真实环境的 Agent 评测
- SWE-bench: 软件工程任务评测
- WebArena: Web 操作评测
- GAIA: 通用 AI 助手评测
- τ-Bench: 工具使用评测

### 3、Agent 测试策略

测试金字塔（从底层到顶层）：

Layer 1：工具单元测试

- 测试每个 Tool 函数的输入输出
- 确保工具在 LLM 调用钱已经正确


Layer 2：Agent 行为测试

- 给定输入，验证是否调用了正确的工具
- 验证 tool_calls 的参数是否正确
- Mock LLM 的返回，测试 Agent 循环逻辑


Layer 3：端到端测试

- 完整运行 Agent，验证最终输出
- 使用 LLM-as-Judge 评分
- 覆盖典型场景和边界情况

Layer 4：回归测试

- 收集线上的 bad case
- 每次改动后验证这些 case 是否退化
- 持续积累评测集


你怎么测试 Agent 代码？

分层测试：【单元测试工具】 - 【Mock 测试 Agent 行为】 - 【LLM-as-Judge 测试端对端】- 【线上回归评测集】



### 4、生产环境最佳实践

1、错误处理

- 每个工具调用都要 try-catch
- 给 LLM 返回【能帮他修正】的错误信息
- 设置全局超时和最大重试次数（避免长时间无响应、无限循环）


2、可观测性

- 记录每次 LLM 调用的输入/输出/token/耗时
- 记录每个 tool_call 的参数和结果
- 使用 LangSmith/LangFuse等工具做Tracing


3、成本控制

- 用更小更便宜的的模型做简单任务（模型分层）
- 缓存相同/相似的 LLM 调用
- 设置 max_tokens 限制每次调用的成本上限
- 用语义缓存减少重复查询


4、安全防护

- Prompt Injection 防护（输入过滤）
- 工具权限最小化（sudo 问题）
- 人工确认 （Human-in-the-Loop）对关键操作


5、性能优化

- 并行执行独立的工具调用
- 流式输出（streaming）提升用户体验
- 预加载和预计算


生产环境 Agent 和 Demo 的区别？

- 目标不同：Demo 追求【能跑】；生产追求【稳定、安全、可观测、低成本】
- 基础设施：生产需要监控、告警、降级、熔断等
- 错误处理：Demo 打印日志，生产 自动恢复+通知



### 5、总结

1、Agent 评估

- 多维度评测：任务完成率、工具使用正确率、执行效率、鲁棒性、安全性、用户体验
- 方法组合：确定性断言、人工标注、LLM-as-Judge、线上反馈
- 公开 Benchmark：AgentBench、SWE-bench、GAIA等只能作为带日期的外部参照
- 应特别检查任务污染、不可复现 harness 和有缺陷的测试用例


2、Agent 测试

- 分层测试：工具单测、行为测试、端对端测试、回归测试
- LLM-as-Judge 是端对端测试的核心方法

3、生产最佳实践

- 错误处理：try-catch + 可读性错误
- 可观测性：Tracing + Logging（记录 LLM 调用的/输入/输出/token结果、记录工具调用参数/结果）
- 成本控制：模型分层（简单问题便宜模型） + 缓存（相似相同问题缓存） + 限制（设置max_tokens限制调用成本上限）
- 安全：Prompt Injection防护（输入过滤） + 权限最小化 + 人工确认
- 性能：并行执行独立工具调用 + 流式输出 + 预加载/预计算
