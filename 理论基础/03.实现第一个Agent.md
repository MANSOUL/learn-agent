# 实现第一个Agent

### 1、调用 LLM（底层）

发送提示词，获取 LLM 的回复，是最基础的 LLM 调用；也是 Agent 最底层的操作：让 LLM 思考。后续所有的 Agent 逻辑都建立在此基础之上。

### 2、Function Calling（核心） --- Agent 的 【手】

Function Calling 是 Agent 最核心的操作，LLM 不只是生成回复文本，还能决定调用什么函数，传什么参数。

流程：

用户：北京今天天气怎么样？
->
LLM 分析 -> 识别需要调用 get_weather 函数
->
LLM 输出： `{"name": "get_weather", "arguments": {"city": "北京"}}`
->
我们的代码执行这个函数，拿到真实数据
->
把函数执行结果返回给 LLM，LLM组织成自然语言回答用户


### 3、实现 Agent 循环（本质） --- 理解底层原理

每个 Agent 的运行本质上是一个循环，称之为【ReAct】循环（Reasoning + Acting）；

循环的 4 个步骤如下：

```
1、拿到用户输入，发给 LLM（Think）
2、LLM 判断：输出结果？调用工具？
  - 输出结果：进入第4步骤
  - 调用工具：进入第3步
3、执行工具调用（Act）- 结果发回给 LLM - 回到步骤1
4、输出最终答案结束循环
```

为什么需要循环？
因为 LLM 可能需要多次调用工具：

【北京和上海哪个更热？】Agent需要：
第一轮 LLM - 判断需要 get_weather("北京")
第二轮 LLM - 拿到北京天气后，还需要 get_weather("上海")
第三轮 LLM - 比较两个城市的温度 - 给出最终答案

这就是 ReAct 循环的核心价值，不是单次推理，而是【推理 - 行动 - 观察 - 推理】的持续过程
