# Agent 核心组件

### 1、规划器（Planner） --- Agent 的 指挥中心

规划起负责决定 【下一步该做什么】。

不同的规划策略适用于不同的场景。

| 策略 | 核心思想 | 适用场景 |
| ---- | ---- | ---- |
| ReAct | 边推理边行动 | 中小复杂度的场景 |
| Plan-Excute | 先制定整体计划再执行 | 需要分解步骤执行的场景 |
| Reflexion |  执行后自后反思改进 | 需要不断迭代优化的场景 |
| LLMCompiler | 分析依赖后并行执行 | 步骤可并行的场景 |

**1.1 ReAct 对比 Plan-Excute：**

ReAct 边推理边行动，每一步都需要重新推理，灵活但效率不高；
Plan-Excute 一次性规划所有的计划，后按计划行动，效率高但不灵活；
日常需要结合两者使用，高层使用 Plan-Excute ，在 Plan-Excute 的步骤中使用 ReAct。

ReAct 是规划器的一种简化形态：它不做全局多步规划，而是每轮做一次"思考-行动-观察"的增量规划，好处是简单灵活、对意外情况反应快，坏处是长任务容易走偏（没有全局视野）。复杂 Agent 现在一般用混合模式：先出个粗计划，再用 ReAct 循环细粒度执行每一步，跑偏了就 replan。

**1.2 Reflexion 反思器**

在 ReAct的基础上叠加了一层【自我审视】机制。

工作方式：

第一轮：Agent 正常推理 -> 回答 A
第二轮：将回答 A 发回给同一个 LLM，问他【这个回答哪里不好，怎么改进？】
第三轮：Agent 根据批评意见重新推理 -> 产生 A‘

和 Plan-Execute 的区别：

>Plan-Execute：先规划再执行；
Reflexion：先执行，事后再反思；
两者结合：Plan-Execute 制定大计划，执行每一步后，再用 Reflexion 审查反思改进。

Reflexion 的额外开销：

> 每轮推理会增加一次或多次模型调用；具体成本和质量需根据任务集实测。
> 适用于要求精确性较高的任务（法律文书、医疗建议、代码审查）

### 2、记忆系统（Memory）--- Agent 的 大脑存储

记忆系统是 Agent 的核心差异点。【为什么呢？】

**三类记忆：**

1、长期记忆（Long Term）
  - 是啥：跨会话的持久性存储
  - 怎么存：向量数据库（Milvus/ChromaDB/Pinecone）、本地文件
  - 用途：用户偏好，知识积累

2、短期记忆（Short Term）
  - 是啥：当前对话上下文，聊天记录
  - 怎么存：存在 messages 列表中
  - 用途：让 LLM 根据上下文，更好的理解当前问题
  - 局限：受到 LLM 上下文窗口限制（128k tokens）

3、工作记忆（Working Memory）
  - 是啥：当前对话任务的工作中间状态
  - 怎么存：存在内存中（变量、字典等）
  - 用途：支持 Agent 完成当前任务的后续工作

**LLM 如何解决上下文窗口限制？**

- 摘要：将历史长对话让 LLM 总结成摘要
- 滑动窗口：只保留最近的 N 轮对话
- 向量检索：将历史存入向量库，按相关性检索
- 混合策略：短期用滑动窗口，长期用摘要+向量检索

**每次对话都带上所有历史对话，会多消耗token吗？如何解决？**

会的；主要通过下列手段优化：

- 上下文压缩：历史太长时自动摘要或截断早期消息，避免无限膨胀
- 按需触发工具：不是每轮都把所有文件内容塞进去，只有调用工具时才读取相关文件
- 只传必要的历史轮数（如最近 5 轮，而不是全部）
- 摘要代替原文（把早期对话压缩成一段摘要）
- RAG 检索代替全文
- System Prompt缓存（Anthropic 和 OpenAI 都支持，重复的 system 部分只计费一次）


### 3、工具设计（Tool Design）--- Agent 的 武器库

工具 是 Agent 与外界交互的唯一方式，工具设计的好坏直接影响 Agent 的可用性。

工具设计的 四大准则：

- 描述要清晰：描述是 LLM 决定是否要调用此工具的唯一依据
  - ❌ 查询天气信息（模糊）
  - ✅ 用于查询指定城市的天气信息，返回温度、湿度、风向信息

- 职责要单一：一个工具只做一件事
  - ❌ search_and_summarize（搜索并总结，两个功能）
  - ✅ 拆分成 search 和 summarize 两个工具

- 错误要可读：返回的错误信息要能帮助 LLM 修正
  - ❌ return Error 404
  - ✅ rerurn 未找到 陪京 的天气信息，你指的是北京吗？

- 参数限定：用 enum 限定参数值，减少 LLM 幻觉
  - parameters: {"city": {"enum": ["北京", "上海", "深圳"]}}

**工作描述怎么写：**

- 什么时候应该调用这个工具
- 这个工具不擅长做什么
- 举例说明典型调用场景

### 5、总结

核心要点回顾：

1. 规划器 (Planner)
ReAct: 每步推理，灵活 (面试高频)
Plan-Execute: 先规划后执行，高效
Reflexion: 自我批评改进
实际项目：组合使用
 

2. 记忆系统 (Memory)
短期记忆: 对话上下文，受窗口限制
长期记忆: 向量数据库持久化
工作记忆: 当前任务的中间状态
面试重点：上下文窗口管理策略
 

3. 工具设计 (Tool Design)
描述要详细、准确
职责要单一
错误信息要可读
这是区分初级/高级 Agent 工程师的关键技能
 

面试速记：

"请描述 Agent 的核心架构"

→ Agent = LLM + Planner + Memory + Tools

→ 通过 ReAct 循环协调各组件工作

→ 记忆系统解决上下文限制，工具系统扩展能力边界
