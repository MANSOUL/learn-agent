# Agent类型与设计模式

五种类型：

| 类型 | 特点 | 场景 |
| --- | --- | --- |
| ReAct | 每步推理 | 最通用 |
| Plan-Execute | 先制定全局计划，再执行 | 结构化任务 |
| Reflexion | 先执行，再反思 | 需要不断迭代优化的高精确性任务 |
| Tool-Calling Agent | 纯工具调用 | 不需要推理的任务 |
| Multi-Agent | 多角色协作 | --- |

关键区别：

| 类型 | 规划方式 | 任务复杂度 | 错误恢复 | Token消耗 | 执行效率 | 典型场景 |
| --- | --- | --- | --- | --- | --- | --- |
| ReAct | 动态推理 | 中等 | 自动 | 中等 | 中等  通用 |
| Plan-Execute | 前置规划 | 强 | 需重新规划 | 低 | 高 | 数据分析 |
| Reflexion | 动态+反思 | 强 | 强（反思） | 高 | 低（多次） | 代码审查 |
| Tool-Calling | 不规划 | 弱 | 弱 | 低 | 高 | API 网关 |
| Multi | --- | --- | --- | --- | --- | --- |


ReAct：边推理边行动、但灵活但效率低；

Planner-Execute：全局规划、高效率、不灵活；

大型任务先 Planner-Execute 做顶层规划，再 ReAct 做每步执行；Reflexion 也可结合做执行完后的反思优化。


### 1、ReAct Agent

ReAct = Reasoning + Acting （推理 + 行动）

执行流程：

推理 -> 行动 -> 观察 -> 再推理 -> 再行动 -> ... -> 得出最终答案

示例：

1、“总结关于这篇文章 xxx”
2、需要获取 xxx (推理)
3、获取 xxx (行动)
4、xxx 的内容（观察）
 -> 基于 xxx 内容继续推理， 直到给出最终答案

伪代码：

```
while(true):
  messages = [xxx]
  response = llm.think(xxx)
  tools = response.get_tools()
  if (!tools):
    return reponse.get_final_anwser()

  for act in tools
    result = act()
    messages.append(result)
```

### 2、Plan-Execute Agent

先全局规划，再执行；

执行流程：

1、分析任务
2、为任务制定详细的执行计划
3、执行计划中的每一步
4、汇总各个步骤结果
5、生成最终答案

使用场景：

- 任务步骤明确、有依赖关系
- 数据分析报表生成
- 代码审查流水线
- 工作流自动化

[Plan-Execute Agent的代码实现](../codes/01_05/c02_plan_execute_agent.py)

### 3、Reflexion Agent

先执行，再反思，改进，再执行，再反思，再改进...，直到获取满意的最终结果

执行流程：

1、初次执行任务，获取执行结果
2、基于执行结果+评估标准，来自我打分+找问题，再次获取提升后的结果
3、基于提升后的结果+评估标准+问题，自我打分+找问题，再次获取提升后的结果
4、重复直到满意

Reflexion 不改变 Agent 的基础能力，
而是通过【反馈循环】让 Agent 在实践中变得更好。

### 4、Agent 模式选择器

如何为任务选择合适的 Agent 类型？

| 任务特征 | 推荐 Agent 类型 |
| --- | --- |
| 需要实时搜索/计算 | Tool-Calling |
| 开放式推理 + 工具调用 | ReAct |
| 步骤明确、可预先规划 | Plan-Execute |
| 需要高质量输出、可迭代 | Reflexion |
| 多角色协作 | Multi-Agent |
| 简单问答 | 直接调用 LLM |
